# VideoSearch 桌面端开发设计文档

## 1. 文档目标

本文档用于指导将 `D:\demo\python\VideoSearch` 的既有功能重构为 `Vue 3 + Electron + FastAPI` 桌面端软件。

设计原则：

- 后端严格遵循 `规范文档/后端规范文档.md`
- 前端严格遵循 `规范文档/前端规范文档.md`
- 不保留旧项目 `/api/*` 路由和旧响应结构，统一迁移到 `/api/v1/*`
- 不引入 Element Plus，前端统一使用自定义组件、Tailwind CSS、FontAwesome
- 首版不设计登录、权限、用户管理和数据库迁移
- 桌面端只面向本机运行，FastAPI 服务绑定 `127.0.0.1`

## 2. 旧项目功能梳理

### 2.1 已完成能力

旧项目由 FastAPI 后端和 Vue 前端组成，主要功能如下：

| 功能域 | 旧项目能力 | 新项目处理 |
| --- | --- | --- |
| 视频搜索 | 前端获取启用资源站，按资源站并发调用单站点搜索接口 | 保留业务流程，接口按新规范重命名和统一响应 |
| 视频详情 | 通过关键词、页码、站点、视频 ID 重新查询并定位视频 | 保留业务流程，Service 层完成数据定位与异常转换 |
| 播放源解析 | 解析 `vod_play_from`、`vod_play_url`，按 `m3u8/mp4/flv/avi` 分类 | 保留解析规则，沉淀为后端 Service 辅助函数 |
| 视频播放 | 前端使用 `hls.js` 播放 m3u8，普通 URL 使用 video 标签 | 保留，改造成标准业务组件 |
| 资源站管理 | 读取 JSON 配置，支持启用/禁用、连接测试、批量测试 | 保留，配置文件落到桌面应用数据目录 |
| 系统日志 | 查询、过滤、统计、清空 JSON Lines 日志 | 保留，接口改为分页结构 |
| 系统监控 | 基于日志聚合活跃用户、搜索成功率、响应时间、错误趋势、热门关键词 | 保留，作为桌面端运行状态模块 |
| 搜索状态缓存 | Pinia + localStorage 保存搜索结果、分页和 Tab 状态 | 保留，过期策略继续使用前端本地状态 |

### 2.2 不纳入首版的能力

| 功能 | 原因 |
| --- | --- |
| 历史记录 | 旧项目仅有占位页面，无完整业务实现 |
| 用户管理 | 旧项目无完成的用户、登录、权限流程 |
| 远程部署模式 | 新项目定位为桌面端本机软件 |

## 3. 目标架构

### 3.1 总体结构

```text
Electron 主进程
  ├─ 创建桌面窗口
  ├─ 启动/停止本地 FastAPI 子进程
  ├─ 向渲染进程暴露最小化桌面能力
  └─ 管理应用数据目录

Vue 3 渲染进程
  ├─ 搜索、详情、播放、设置、日志、监控页面
  ├─ Pinia 管理页面状态
  ├─ Axios 调用本机 FastAPI
  └─ HLS.js 播放视频源

FastAPI 后端
  ├─ 资源站配置管理
  ├─ 视频搜索和详情聚合
  ├─ 播放源解析
  ├─ JSON Lines 日志记录
  └─ 日志驱动的监控统计
```

### 3.2 进程职责

| 进程 | 职责 | 禁止事项 |
| --- | --- | --- |
| Electron 主进程 | 窗口生命周期、后端进程生命周期、应用目录定位 | 不写业务搜索逻辑 |
| Electron Preload | 暴露 `backendStatus`、`appInfo` 等只读能力 | 不暴露完整 Node API |
| Vue 渲染进程 | UI、交互、状态、API 调用、播放器 | 不直接读写本地业务文件 |
| FastAPI 后端 | 业务逻辑、外部资源站请求、配置保存、日志聚合 | API 层不直接操作配置或文件 |

### 3.3 数据流

```text
用户输入关键词
  -> Vue 搜索页读取资源站列表
  -> Vue 按启用站点并发调用 /api/v1/videos/search
  -> FastAPI 请求第三方资源站
  -> FastAPI 标准化视频字段和分页信息
  -> Vue 按资源站 Tab 展示结果
  -> 用户进入详情页
  -> Vue 调用 /api/v1/videos/detail
  -> FastAPI 返回视频详情和播放源
  -> Vue 播放器使用 HLS.js 播放
```

## 5. 后端设计

### 5.1 统一响应

所有接口返回：

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

后端统一在 `app/schemas/response.py` 定义：

- `ApiResponse`
- `PaginationInfo`
- `PaginatedResponse`
- `ErrorCode`
- `success()`
- `error()`

API 层只捕获 `ServiceException`，其他异常交由全局异常处理器转换。

### 5.2 错误码映射

| 场景 | ErrorCode |
| --- | --- |
| 参数缺失、页码非法、站点 ID 为空 | `PARAM_ERROR` |
| 站点不存在、视频不存在、日志不存在 | `DATA_NOT_FOUND` |
| 第三方资源站请求失败、响应解析失败、连接测试失败 | `AI_SERVICE_ERROR` |
| 配置保存失败、日志文件写入失败、未知内部错误 | `INTERNAL_ERROR` |

用户可见错误信息保持简短，不暴露 URL、堆栈、文件路径和第三方原始异常。

### 5.3 视频模块

#### 5.3.1 Schema

| Schema | 用途 |
| --- | --- |
| `VideoSearchRequest` | 搜索 Query 参数：`wd/site_id/page/page_size` |
| `VideoDetailRequest` | 详情 Query 参数：`keyword/site_id/vod_id/page` |
| `VideoItemResponse` | 标准视频列表项和详情数据 |
| `PlayEpisodeResponse` | 单集播放项：`name/url` |
| `VideoSearchResponse` | 继承分页结构，增加站点和过滤统计 |
| `VideoDetailResponse` | 视频详情、站点信息 |

`VideoItemResponse` 字段：

```text
platform, id, title, description, thumbnail, view_count,
upload_date, channel, actor, area, language, year, status,
type_name, play_sources
```

#### 5.3.2 API

| 方法 | 路由 | 说明 | 返回 |
| --- | --- | --- | --- |
| GET | `/api/v1/videos/search` | 搜索单个资源站 | `ApiResponse[VideoSearchResponse]` |
| GET | `/api/v1/videos/detail` | 获取视频详情 | `ApiResponse[VideoDetailResponse]` |

请求参数统一使用 snake_case：

- `wd`
- `site_id`
- `page`
- `page_size`
- `keyword`
- `vod_id`

#### 5.3.3 Service 函数

```text
query_video_list(query)
query_video_detail(query)
fetch_site_raw(site, wd, page)
map_video_item(site_id, site_name, item)
parse_play_sources(play_url, play_from)
```

核心规则：

- 搜索前调用资源模块校验站点存在且启用
- 第三方请求统一使用 `httpx.AsyncClient`
- 第三方响应解析失败统一抛 `ServiceException(ErrorCode.AI_SERVICE_ERROR, "服务调用失败，请稍后重试")`
- 过滤 `预告片`、`电影解说`、`影视解说`
- 搜索结果只保留有 `id` 和 `title` 的视频
- 分页结构使用 `lists` 和 `pagination`

### 6.4 Store 设计

| Store | 职责 |
| --- | --- |
| `useSearchStore` | 搜索关键词、搜索结果、Tab、分页、统计、本地缓存 |
| `useResourceStore` | 资源站列表、启用状态、测试状态、批量测试 |
| `useVideoStore` | 当前视频、播放源、当前剧集、播放状态 |

Store 内部使用 camelCase，调用 API 时在 `src/api/*` 中转换为 snake_case。

### 6.5 API 调用规范

`src/utils/request.js` 统一封装 Axios：

- `baseURL` 从 Electron preload 注入值或环境变量读取
- 超时默认 30000ms
- 成功条件为 `code === 0`
- 失败时抛出 `Error(message)`
- 不在页面组件内拼接旧响应结构

示例响应处理：

```text
response.data.code === 0 -> 返回 response.data
response.data.code !== 0 -> throw Error(response.data.message)
```

## 7. Electron 设计

### 7.1 主进程

主进程职责：

- 创建 `BrowserWindow`
- 设置 `contextIsolation: true`
- 设置 `nodeIntegration: false`
- 启动本地 FastAPI
- 监听窗口关闭时停止后端进程
- 定位应用数据目录

### 7.2 Preload

暴露最小 API：

```text
window.desktopApi.getAppInfo()
window.desktopApi.getBackendBaseUrl()
window.desktopApi.getBackendStatus()
```

Preload 不暴露文件系统读写接口。

### 7.3 后端进程

开发阶段使用 `backend/.venv/Scripts/python.exe` 启动 FastAPI 模块。

运行约束：

- Host 固定为 `127.0.0.1`
- Port 固定为 `4740` 并由主进程传给前端
- 后端进程退出时写入系统日志
- 主进程退出时停止后端进程
